# CampusPulse delivery outcomes

- [x] **Multiline input and per-comment sentiment (M1–M2):** Provide a large multiline input; each nonblank line is one independent student feedback comment; ignore blank lines, trim unnecessary whitespace, and normalize repeated spaces. Analyze every comment individually. Every comment receives exactly one of Positive, Negative, or Neutral, with its original text and predicted label displayed together. Handle punctuation, emojis, Unicode, repeated/duplicate comments, and long comments deterministically.

- [x] **Complete, correct statistics and automatic visualization (M3–M4):** Display Positive, Negative, Neutral and total comment counts; display the percentage of each sentiment, calculated correctly from analyzed comments. Automatically update at least one understandable bar or pie visualization whenever analysis changes.

- [x] **Friendly empty state and ordered offline fallback (M5–M6):** For empty input, display a helpful, friendly explanation telling users to enter feedback first; do not crash and do not perform analysis. Use the sentiment-engine priority VADER, then TextBlob, then a built-in sentiment dictionary. If an NLP library is unavailable, automatically switch to the word-list fallback, compare positive and negative word occurrences, infer sentiment, and continue without crashing. Do not train a model. The app must work completely offline after dependencies have been installed. Expected outcomes: “The workshop was amazing and very helpful” → Positive; “The session was too long and boring” → Negative; “The event is on Friday” → Neutral.

- [x] **CSV import and per-row presentation (B2–B3, B5):** Accept CSV files locally; detect likely feedback columns when possible; if multiple text columns exist, let users choose which to analyze. Handle empty/invalid CSV and encoding problems with user-friendly messages. Color-code every analyzed comment Positive green, Negative red, Neutral grey, while retaining readable textual labels and accessible meaning without color alone. Show intuitive 😊 Positive, 😞 Negative, and 😐 Neutral cues.

- [x] **Verdict, lexical and campus insights (B1, B4, advanced insights):** Derive an overall verdict from the calculated statistics, including Mostly Positive Feedback, Mostly Negative Feedback, Mostly Neutral Feedback, Mixed Opinions, and Balanced Feedback as appropriate. Show the most common words in positive and negative comments, ignore stop words, and include frequency counts/visualizations where appropriate. Generate summaries from analyzed data, not hardcoded: what students liked/disliked most, frequently mentioned issues, recommended improvement priorities, strengths and weaknesses. Where feasible, identify commonly mentioned places, departments, facilities or services (e.g., Wi-Fi, Canteen, Library, Parking, Hostel, Laboratory, Classroom, Block A) and rank praise/criticism; where feasible, identify aspects separately in mixed praise/criticism comments.

- [x] **Resilient, responsive, accessible and maintainable operation:** Gracefully handle invalid input, unexpected exceptions, hundreds or thousands of comments, emoji-heavy and mixed-language feedback, duplicate comments, invalid characters, very long comments and feedback containing praise and criticism; show helpful user-facing errors rather than raw errors. Optimize responsiveness and memory use, prevent duplicate processing and unnecessary recalculation, and keep the interface responsive during processing. Provide readable type, sufficient contrast, keyboard navigation, meaningful labels, and do not rely on color alone. Provide informative success/error messages and loading indicators when needed. Use clean abstractions, descriptive names and maintainable code. Support light/dark themes if feasible.

- [x] **Useful report outputs:** Allow export in useful formats, including at least CSV; include JSON and print-friendly report output if feasible. Reports should include results and useful statistics/summaries where appropriate. Core analysis must not rely on optional AI; optional local AI, if any, may only assist summary/insights and may not be required for functionality.
